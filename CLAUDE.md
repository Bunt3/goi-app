# Goi 語彙 — working notes for coding sessions

Personal Japanese vocabulary PWA for one user. Read `HANDOFF.md` for current status and open work, and `README.md` for user-facing behaviour and the JSON schema.

**Start with the "NEXT TASK" section at the top of `HANDOFF.md`.** It is the active assignment, with the design, the order of work and the facts already checked.

## Hard constraints (from the owner; do not relax without asking)

- Installable, offline-first PWA. One codebase for Android (Brave/Chrome) and Windows desktop (Firefox, Brave).
- Vite + TypeScript, vanilla DOM. Runtime dependencies are `ts-fsrs`, `dexie`, and `tesseract.js` (lazy-loaded; added when the owner asked for image capture). No framework, no backend, no accounts, no analytics. Do not add others without the owner asking for the feature that needs them.
- **No requests to any other origin, ever.** No web fonts, CDNs, lookups or uploads. The browser run-through asserts this. The same-origin fetches after install are the OCR engine and model under `ocr/` on first use, and the dictionary under `dict/` when the owner presses Download.
- Served from `https://bunt3.github.io/goi-app/`. The base path lives in `vite.config.ts` (`BASE`) and `public/manifest.webmanifest` (`id`, `start_url`, `scope`).
- Sessions are 5-minute bursts. Never add streaks, guilt wording, or anything that punishes skipped days.
- Mobile-first, controls within thumb reach, dark by default.

## Commands

```bash
npm test            # Vitest, runs in Node with TZ=Asia/Tokyo
npm run build       # copies OCR assets to public/ocr, builds public/dict if DICT_SOURCE is set, tsc --noEmit, vite build (also emits dist/sw.js)
npm run build:e2e   # the same, with the 51-entry test dictionary (tests/fixtures/dict-sample.json)
npm run e2e         # headless run-through of dist/; needs build:e2e first
npm run dev         # no service worker in dev
```

Playwright is not a dependency. `e2e/runthrough.cjs` uses `require('playwright')` from the environment.

Before calling work done: `npm test`, `npm run build:e2e`, `npm run e2e` all green. Pushing to `main` deploys to GitHub Pages via `.github/workflows/deploy.yml`.

## Invariants that are easy to break

- **Pure modules stay DOM-free.** `srs/`, `data/`, `dict/`, `day.ts`, `cards.ts`, `textpick.ts` run under Node in tests. Browser APIs belong in `ui/`, `tts.ts`, `backupfs.ts`, `furigana.ts` (DOM-building half only).
- **`Card.updated` is bumped only by text edits and deletion, never by reviews.** Merge depends on this to keep an edit on one device and reviews on another.
- **Every change to scheduling state writes a review log.** Merge decides progress by comparing log sets and may rebuild state with `replayLogs`. A manual reset is a log with `rating: 0`. State changed without a log will be silently undone by a later merge.
- **Deletes are tombstones** (`deleted: true`), never row removals. `store.live()` filters them; `store.cards` includes them.
- **Daily counters are derived from today's logs**, not stored, so they survive imports. The study day rolls over at 04:00 local (`day.ts`).
- **Mutations call `store.onChange`**, which schedules folder backups. A new `Store` write method must call it.
- **Backups commit after the write.** Use `store.prepareBackup()` and call `commit()` only once the file is written, so a failed write is not recorded as a backup.
- **An empty deck is never auto-backed-up** (`store.cards.size === 0` guard). Keep it: it stops a wiped browser overwriting a good backup.
- **Starter-deck card ids are deterministic** (`uuidFromName('<idPrefix>:word:reading')`; the Workplace deck uses `seed`, others `pack:<id>`). Changing a prefix, or an entry's word or reading, creates a duplicate on devices that already loaded the deck. Workplace cards keep `source: 'seed deck'`: the schema-2 migration puts cards with that source into the Workplace deck.
- **Checks are a card field (`check`, schema 3)**, set only by checker mode (`store.setCheck`, a content edit). Never show check status while studying or browsing; the owner asked for it to stay inside checker mode (plus the note on a flagged card's edit screen). The old `seed-unverified` tag is stripped by the schema-3 migration; don't reintroduce it.
- **Decks are a card field (`deck`, schema 2).** Moving a card between decks is a content edit (bumps `updated`). Which decks are studied is a per-device setting (`studyDecks`); stale names are ignored, and none left means all. Queue-building screens use `store.studying()`, not `store.live()`.
- **Schema changes.** Adding an optional `Settings` field needs only a default and a line in `parseSettings`. Changing `Card` or `ReviewLog` needs a `SCHEMA_VERSION` bump, a migration in `parseExport`, a Dexie `version()` upgrade in `db.ts`, and a README update.
- **`h()` in `ui/dom.ts`:** `null`/`undefined` props are skipped; `false` is skipped unless the key is a real DOM property. Children may be `null`/`false`, but native `replaceChildren`/`append` do not accept `null`.
- **OCR preprocessing is load-bearing.** `prepareForOcr` widens a hand-drawn box, upscales small regions, adds a border in the background colour, and inverts dark images. Each was added because a test image was misread without it; text within a few pixels of the edge turns to garbage. Re-run the run-through's OCR steps after touching it.
- **OCR files live in their own cache** (`goi-ocr-<tesseract version>`), fetched on first use and kept across app updates. They are not in the precache list on purpose (13 MB on disk). The `activate` handler must keep exempting that cache.
- **While the word-picker sheet is open, the review screen ignores keys** (`pickerOpen()`), otherwise typing a reading would rate the card underneath.
- **The service worker source is a template literal inside `vite.config.ts`.** No backticks inside it. Cache lookups use `ignoreVary` on purpose.

- **The dictionary lives in its own database (`goi-dict`).** Never read it from backups, merges, `deckMark` or the `Store`. Removing it must never touch cards. Its files under `dict/` are not cached by the service worker (the database is the copy).
- **The dictionary never overwrites a field the owner typed.** `AutoFill` only writes empty fields or fields it (or the IME reading) filled. Cards keeping a dictionary reading or meaning get the `auto-filled` tag. No unattended bulk fill: homographs make it wrong too often.
- **A deploy must survive a failed dictionary download.** Every dictionary step in `deploy.yml` is `continue-on-error`, and `DICT_OPTIONAL=1` makes `build-dict.mjs` warn and build without one. The app then says "Dictionary not available in this build".
- **Interface language is a translation layer over rendered English** (`src/ui/i18n.ts` + `src/i18n/ja.ts`). New UI text needs a catalogue entry (exact string, or a pattern for text with numbers or names) or it shows in English in Japanese mode. Anything showing the owner's content (meanings, examples, tags, sources, glosses) must carry `data-content` so it is never translated. Don't use `[translate="no"]` for this: `<html>` already carries it to stop browser auto-translation. Never map a string to itself (the observer would loop); a test checks this.
- **Share target:** the manifest's `share_target` points at `/goi-app/share`; `main.ts` reads it before mounting and replaces the URL with `#/capture`. The service worker serves that path from the cached shell (navigation fallback), so it works offline.
- **Keigo drill ids are `v:<id>:son|ken`, `w:<casual>`, `p:<casual>`, `f:<form>`, `u:<text>`.** Changing one orphans that item's progress (harmless: it is just practised again).
- **The deinflection table is the app's own.** Don't paste in Yomitan's or another GPL project's rules.

## Conventions

- Epoch milliseconds everywhere for time. No `Date` objects in stored data.
- Tests take time as an argument; nothing in pure code calls `Date.now()` implicitly except as a default parameter.
- User-facing wording is plain and neutral. Failures say what happened and what to do; nothing fails silently.
- New behaviour gets a Vitest test in the pure layer and, if it has UI, a step in the run-through.
